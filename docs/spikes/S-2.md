# S-2 — Piano touch-to-tone latency (PENDING: physical devices)

**Threshold (go):** median touch-to-tone ≤ 40 ms on the mid-range device. Above ~60 ms, revisit sample loading and buffer
strategy before building the keyboard.

**Blocks:** the Oboe sampler and the keyboard UI (§8.1, §8.2). Per the delegation prompt, neither has been started;
`PianoCaptureGate.ENABLED = false` keeps the mode pills disabled.

## Devices

Flagship · mid-range · low-end Transsion. None run in this pass.

## Protocol

1. Build the latency probe (`spikes/s2-latency`, to be added with the sampler): an Oboe output stream in Exclusive +
   LowLatency mode playing a 5 ms click on touch-down, with `AAudio`/OpenSL fallback logged.
2. Record the screen tap and the speaker with a second phone at 240 fps, or use a piezo + line-in loopback; 30 taps.
3. Report median, p90, `framesPerBurst`, granted buffer size, sharing mode, and whether the performance mode was honoured.

**Fallback if no-go:** larger sample pre-roll in RAM, `setBufferSizeInFrames(burst)` after warm-up, and if still above
60 ms on mid-range, ship Voice-only for Milestone 1 and keep Piano behind the gate.
