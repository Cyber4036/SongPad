# S-5 — Navigation 3 prototype (PENDING: physical devices)

**Threshold (go):** library → song detail with an active recorder: no state-restoration or back-stack defects; predictive
back works.

**Status:** the real shell is built (`app/src/main/kotlin/com/songpad/app/MainActivity.kt`, Navigation 3 1.1.7) and
compiles; the two-screen protocol has not been run on a device.

## Protocol

1. Enable "Don't keep activities" and predictive back animations in developer options.
2. Library → Record → start recording → home → return: the recorder screen and its state survive.
3. Library → Song → Takes tab → play → rotate → predictive back gesture: playback continues, the ribbon stays, the
   back gesture previews the library.
4. Kill the process from the recents screen while on Song detail; relaunch: the back stack (Library › Song) restores from
   the serialized keys and the song is re-observed (not cached).
5. Nudge deep link (`adb shell am start -a android.intent.action.VIEW -d songpad://song/<id>`) lands on the song with a
   sane stack; a deleted id lands on the library.

**Fallback if no-go:** Navigation Compose (Nav2). Navigation is centralized in `MainActivity.kt`; the estimated swap is
~2 days (ADR-0003).
