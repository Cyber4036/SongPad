## Key Hardware Finding & Driver Resilience Fix

During initial testing on the Galaxy A02, an important kernel/HAL vulnerability in low-end MediaTek chipsets was identified and resolved:

* **Root Cause**: The MediaTek MT6739 ALSA kernel driver does not implement hardware input timestamping (`pcm_get_htimestamp fail, ret = -1` in kernel logcat). Consequently, Oboe's `stream->getTimestamp(CLOCK_MONOTONIC, ...)` returns an error for input capture streams. This previously prevented `ClockMapping` from receiving hardware anchors and defaulted note events to frame 0.
* **Resolution**:
  1. **HAL Fallback in C++ (`CaptureEngine::timestamp()`)**: When `stream->getTimestamp` returns an error, the engine automatically falls back to atomic `framesCaptured_.load(std::memory_order_acquire)` and `clock_gettime(CLOCK_MONOTONIC)`.
  2. **Defensive Anchoring**: `OboeAudioRecorderEngine.start()` seeds an initial anchor at $(0, t_0)$, and `CaptureWriterThread.maybeAnchor()` falls back to atomic `framesWritten` if native timestamps are ever missing.
* **Result**: Tested and confirmed stable with 0 xruns and +3.73 ppm alignment across 7 minutes.
