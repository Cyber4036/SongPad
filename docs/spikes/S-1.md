# S-1 — Recorder crash recovery (PENDING: physical devices)

**Threshold (go):** after 30 minutes of continuous capture followed by `adb shell am kill com.songpad.app.debug`, the
partial `audio.pcm.tmp` decodes cleanly to its last synced byte and ≤ 1 s of audio is lost.

**Blocks:** all capture work (§7) is *built*; this spike validates it. Do not ship Milestone 1 without it.

## Protocol

1. Install the debug APK; grant microphone; play a 1 kHz tone with 1 s ticks near the mic (a metronome app on a second phone).
2. Start a Voice take, lock the screen at minute 5, background the app at minute 10, take a call at minute 15 (decline it),
   keep recording to minute 30.
3. `adb shell am kill com.songpad.app.debug` (not `force-stop`; the FGS must be what keeps it alive, and kill must be abrupt).
4. `adb pull /data/data/com.songpad.app.debug/files/takes/<id>/audio.pcm.tmp` (debug build, run-as).
5. `sox -r 48000 -e signed -b 16 -c 1 audio.pcm.tmp out.wav`; count ticks; compare to wall clock.
6. Relaunch: the §9.4 prompt appears once; Keep → the take is listed as "Recovered recording", plays, transcodes.

## Record

- frames written at kill (logcat `OboeAudioRecorderEngine`), file length / 96,000 = seconds on disk, ticks counted.
- XRun count, longest fsync (see docs/audio/BUFFER_SIZING.md).
- Whether the FGS notification survived the lock screen and the call.

**Fallback if no-go:** `AudioRecord` on a dedicated `THREAD_PRIORITY_URGENT_AUDIO` thread behind the same
`AudioRecorderEngine` contract (ADR-0008). The file strategy and recovery path are unchanged.
